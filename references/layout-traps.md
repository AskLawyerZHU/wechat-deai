# 排版层 AI 痕迹

## 为什么要单列一层

公众号的 AI 感有两个来源：

- **内容层**：模型写出来的句子。用词表、句法、配额可以治。
- **排版层**：模板拼出来的外壳。英文大写标签、重复编号、未渲染的模板语法、塌成文字块的表格。

读者不会区分这两者。一个裸露的 `}` 和一个"赋能"，在他眼里是同一件事——这文章是程序做的。

排版层的痕迹还有一个特点：**原稿越干净，它越刺眼**。正文写得越像人，那些模板残渣就越突兀。

## 判断方法

拿原稿 markdown 和线上页面逐项比对。

| 原稿 | 线上 | 判定 |
|---|---|---|
| 干净 | 脏 | 问题在排版环节，回去修模板，**不要动文章** |
| 脏 | 脏 | 内容层问题，走六层扫描和重写动作 |
| 干净 | 干净 | 不用改 |

比对的第一步永远是读原稿。跳过这一步就开始"去 AI 味"，会把排版事故当成写作问题来改，越改越远。

## 六类排版痕迹

### 一 英文大写标签

**表现**：`OPENING`、`ROUND ONE`、`THE SKILL`、`INSTALL`、`DEEPER`、`THE END`、`PART 01`、`CASE STUDY`。

**为什么最重**：它暴露的不是用词，是**结构不是自己想出来的**。中文公众号里出现英文大写标签，读者的第一反应是"套模板"。

**修法**：整组换回中文短句小标题。如果原稿本来有中文小标题，说明它们被模板覆盖了，恢复原样即可。

**保留例外**：设计风格刻意为之（例如整号统一使用英文标签作为视觉识别），且全年一致。偶尔一篇出现，就是模板残渣。

### 二 重复编号系统

**表现**：开头一套「本文看点 01／02／03」，正文又来一套「01…07」。同一个页面出现两个"03"。

**为什么有害**：读者读到第二个"03"会以为自己翻错页，划走。而且"本文看点"提前剧透后文，还挤掉了真正的开场。

**修法**：删掉前置导航。三个要点在后文都会正面讲到，不需要预告。

**保留例外**：五千字以上的长文、且导航只出现一次、且不编号。

### 三 模板语法泄漏

**表现**（按出现频率）：

| 残留 | 来源 |
|---|---|
| `{{#ff6b35 文本}}` `{{title}}` `{{var}}` | 自定义颜色／变量语法未渲染 |
| `...bash` `...python` | 代码围栏语言标记外露 |
| ` ``` ` | 代码围栏未闭合或未转换 |
| `**文本**` | markdown 加粗未转换，读者看到星号 |
| `## 标题` | markdown 标题未转换，读者看到井号 |
| `\|` 竖线 | 表格管道符外露 |
| `[链接](url)` | markdown 链接语法外露 |
| `&nbsp;` `&amp;` | HTML 实体外露 |

**修法**：改用模板支持的标准语法。发布前全文搜一遍上面这些符号。

**这是最刺眼的一类。** 一个裸露的 `}` 出现在句子末尾，比十句"赋能"更能说明这文章是拼出来的。

### 四 表格塌陷

**表现**：三列 markdown 表格在线上变成一行连读的文字，例如「特点具体做什么挡住什么坑」。

**原因**：公众号编辑器不支持 markdown 表格。

**危害**：这不是风格问题，是**信息丢失**。三列的对应关系没了，读者读不出"特点 A 挡的是坑 A"。两张表塌掉，全文最结构化的部分就废了。

**修法**：转成 HTML `<table>`，或做成图片卡。转 HTML 时保持原列数，不要为了适配手机压成两列。

### 五 图注与图片位错位

**表现**：破折号加一行字充当图注（`— 终本记录的数字`）；图片丢失只剩图注；图注与图片内容不对应。

**危害**：破折号图注在全篇反复出现时，会形成一种机械的节奏——每个小节都是"破折号＋短语"，读者能感觉到填充。

**修法**：图注写在图片下方，一句话说明这张图在证明什么，不用破折号当装饰。

### 六 装饰滥用

**表现**：`📌` 开头的导航块、每节一个小圆点编号、分割线过密、金句卡连续两张、emoji 出现在每个小标题前。

**危害**：装饰密度过高时，读者注意力被格式吃掉，读不到内容。而且这些装饰通常是模板统一的，不是内容需要的。

**修法**：装饰只在内容确实需要停顿的位置出现。分割线全篇不超过两处。

## 发布前 grep 清单

在排版产物（HTML）上跑一遍，命中即修：

```bash
grep -n -E '\{\{|\}\}|\.\.\.[a-z]+$|^\s*```|\*\*|^#{1,6} |&nbsp;|&amp;|\]\(http' 排版.html
```

再搜英文大写标签：

```bash
grep -n -E '\b(OPENING|ROUND|THE SKILL|INSTALL|DEEPER|THE END|PART [0-9])\b' 排版.html
```

再确认表格没有塌：

```bash
grep -c '<table' 排版.html
grep -c '<tr' 排版.html
```

原稿有几张表，排版产物就应有几个 `<table>`。数量不匹配，说明有表塌了。

## 与原稿比对的操作顺序

1. 读原稿 md，记下小标题、表格数量、代码块数量。
2. 读线上页面（或排版 HTML），逐项核对上面三项。
3. 三项中有任何一项不一致，先修排版，再谈去 AI 味。
4. 排版修完，回到内容层的六层扫描。

反过来做（先改内容）会浪费一轮——你改好的句子，下一版排版可能又被模板覆盖一遍。
